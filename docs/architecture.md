## Scenario

A fictional retailer, **Retail 360**, wants a single governed view of customers, products, stores,
orders and in-store activity. Order and master data live in an on-premises ERP SQL Server; point of
sale (POS) terminals emit a real-time event stream. Analysts need daily KPIs in Power BI, data
scientists need clean history for models, and applications need low-latency access.

## Data flow

| Step | Component | What happens |
| --- | --- | --- |
| 1 | Azure Data Factory | A tumbling-window trigger starts `PL_Master_Ingest` daily (24 h window, 1 h delay). It reads `ingestion_config.json`, then fans out `PL_Ingest_Entity` per enabled table through a self-hosted IR. Each run writes `landing/erp/<entity>/<entity>_<yyyyMMdd>.csv`. |
| 2 | Event Hubs | POS terminals publish JSON to the `pos-events` hub. Capture writes an Avro copy to the `archive` container for replay; Databricks reads the Kafka endpoint for the low-latency path. |
| 3 | Bronze | Auto Loader (files) and Structured Streaming (Kafka) append raw data to `bronze.*` Delta tables with `_ingested_at`, `_source_file` and `_batch_id`. Schemas are all-string and unexpected columns are rescued, so source drift never fails ingestion. |
| 4 | Data quality gate | `retail360-dq` measures every rule on Bronze, appends to `gold.dq_results`, and fails the job when a blocking rule drops below the threshold. |
| 5 | Silver | A Delta Live Tables pipeline applies the shared cleaning functions and expectations. `apply_changes` de-duplicates (SCD type 2 for customers). Failing rows go to `<entity>_quarantine` tables instead of disappearing. |
| 6 | Gold | `retail360-gold` builds conformed dimensions, `fact_sales` (merged by `order_id`, `line_no`), and aggregates. |
| 7 | Serving | Databricks SQL and Power BI read Gold; ML jobs read Silver and Gold; Cosmos DB and API Management expose selected data products. |

## Design principles

- **Code once, run anywhere.** Cleaning, quality rules and Gold logic are pure PySpark functions in
  the `retail360` wheel. The same code runs in unit tests on a laptop, in jobs and in Delta Live
  Tables.
- **Nothing is silently dropped.** Rejected rows are quarantined with the list of failed rules.
- **Identity over secrets.** Managed identities and OIDC everywhere; the only secret (ERP password)
  is in Key Vault.
- **Everything as code.** Infrastructure (Terraform), orchestration (ADF JSON), compute and jobs
  (Databricks Asset Bundle) and governance (SQL) are versioned and deployed by pipelines.

## Scope: what is implemented and what is reference

| Area | Status |
| --- | --- |
| PySpark transformations, quality rules, DLT pipeline, tests | Implemented and unit-tested locally (see CI) |
| Terraform modules, bundle, ADF definitions, SQL, workflows | Complete and syntax-checked; written to be deployable but **not applied to a live subscription** by the author of this repository |
| Purview scanning, Power BI, Azure ML, Cosmos DB, API Management | Shown in the architecture as the serving and governance targets; no code in this repository |
| SAP and SaaS connectors | Shown as sources; the sample project ingests the ERP tables and the POS stream |

Treat the repository as a reference implementation: review the Terraform plan and adapt names,
network ranges and groups before using it in a real subscription.
